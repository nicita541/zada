# Инструкции для Codex по проекту Zada

## Главные правила проекта

- Не переписывай проект с нуля.
- Не заменяй существующий store.
- Не ломай local-first архитектуру.
- Не делай большой backend refactor, если это явно не попросили.
- Не создавай fake UI без реальных данных.
- Не добавляй Calendar, Habits, Focus или GameDev expansion, если это явно не попросили.
- Все новые пользовательские строки должны идти через i18n.
- Русский язык — язык по умолчанию.
- Делай маленькие локальные изменения.
- Не форматируй файлы, которые не относятся к задаче.
- Не трогай несвязанные модули.
- Не меняй data model, если задача явно этого не требует.

## Направление UI

Zada должна ощущаться как:

- современный task manager;
- спокойное productivity-приложение;
- task-first workflow;
- простая на входе, мощная в глубине.

Zada НЕ должна ощущаться как:

- admin panel;
- developer dashboard;
- CRUD generator;
- Discord-like workspace;
- система управления техническими сущностями.

## UX-приоритеты

- Задачи — главный контент.
- Проекты — вторичный способ организации.
- Sidebar должен помогать навигации, а не доминировать.
- Основные экраны должны быть спокойными и читабельными.
- Редкие или технические поля нужно прятать в “Дополнительно”.
- Интерфейс должен быть понятен обычному пользователю, а не только программисту.
- Today / My Tasks / Board должны быть основными рабочими зонами.
- Project creation не должен доминировать над задачами.
- Skeleton-модули не должны выглядеть как полностью готовые основные разделы.

## Визуальные правила

- Держи одинаковые отступы.
- Не допускай слипшийся текст рядом с иконками, счётчиками, chips и badges.
- Название задачи должно быть визуально главным.
- Метаданные должны быть тише, чем название задачи.
- Завершённые задачи должны быть визуально приглушены.
- Empty states должны быть спокойными, а не похожими на предупреждения.
- Убирай fake metrics и prototype-looking блоки.
- Context menus не должны быть перегружены.
- Частые действия должны быть выше редких действий.
- Удаление должно быть легко найти, но всегда с подтверждением.

## UI-ориентиры

Для Kanban / Board / task cards использовать как направление:

- YouGile board:
  https://ru.yougile.com/team/my-tasks

Для Today / task-first / simple workflow использовать как направление:

- TickTick:
  https://ticktick.com/webapp/#c/all/calendar/m

Не копировать эти сервисы один в один. Использовать только как UX/UI direction.

## Стиль работы с кодом

- Сначала изучи существующие компоненты.
- По возможности переиспользуй существующие компоненты.
- Лучше редактировать существующие файлы, чем создавать лишние абстракции.
- Делай маленький и локальный diff.
- Если нужно изменить больше 8 файлов — остановись и объясни почему.
- Если задача требует широкого refactor — сначала объясни план и риски.
- Не переписывай App.tsx полностью.
- Не заменяй store с нуля.
- Не меняй рабочие API flow без необходимости.
- Не добавляй новые production dependencies без явной необходимости.

## Проверки

Перед большими изменениями:

```bash
git status --short
npm run typecheck
```

После изменений в коде:

```bash
npm run typecheck
npm test
npm run build
```

Если проверку невозможно выполнить из-за окружения — честно напиши причину.

## Формат финального ответа

В конце каждой задачи напиши:

- какие файлы изменены;
- что изменено;
- что пропущено, если что-то не сделал;
- результаты проверок;
- есть ли риски или что нужно проверить вручную.
