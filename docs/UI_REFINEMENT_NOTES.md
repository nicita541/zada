# UX/UI замечания по Zada

## Назначение файла

Этот файл хранит пользовательские UX/UI-замечания по текущему интерфейсу Zada.

Используй его только для задач, связанных с доработкой интерфейса, визуальной структуры, удобства работы с задачами, Board, Today, Sidebar, Task Detail, Notes и Import.

Не используй этот файл как повод начинать большой редизайн всего проекта. Работай маленькими локальными задачами.

---

## Визуальные ориентиры

### YouGile

Ориентир для Kanban / Board / task cards:

https://ru.yougile.com/team/my-tasks

Что нравится:
- компактные карточки задач;
- спокойный dark UI;
- минимум визуального шума;
- фокус на задачах;
- читаемые колонки;
- быстрое сканирование задач глазами;
- проекты не доминируют интерфейс;
- sidebar не перетягивает внимание;
- структура задач читается быстро;
- secondary info тише, чем task title.

Не копировать YouGile один в один. Использовать только как UX/UI direction.

### TickTick

Ориентир для Today / task-first / simple workflow:

https://ticktick.com/webapp/#c/all/calendar/m

Что нравится:
- простой вход в работу;
- быстрый ввод задач;
- task-first подход;
- понятные группы задач;
- минимум лишней информации;
- спокойная визуальная подача.

Не копировать TickTick один в один. Использовать только как UX/UI direction.

## Главная UX-цель

Zada должна ощущаться как:

- task-first приложение;
- современный task manager;
- спокойное productivity-приложение;
- простая на входе, мощная в глубине;
- удобная для ежедневного использования.

Zada НЕ должна ощущаться как:

- admin panel;
- developer dashboard;
- CRUD panel;
- Discord-like workspace;
- система управления техническими сущностями.

---

## 1. Интерфейс ощущается слишком техническим

### Проблема

Иногда приложение выглядит так, будто оно сделано для программиста или администратора, а не для обычного пользователя.

### Нужно

- убрать лишнюю техническую информацию с основных экранов;
- скрыть редко используемые поля в “Дополнительно”;
- сделать основные действия очевидными;
- сделать UI спокойнее, проще и человечнее;
- уменьшить ощущение CRUD/admin panel;
- не показывать technical/debug-looking элементы как основной контент.

### Ожидаемый результат

Пользователь должен сразу понимать:

- где задачи;
- как добавить задачу;
- как открыть задачу;
- как создать проект;
- как переключиться List/Board;
- где настройки.

---

## 2. Sidebar слишком доминирует

### Проблемы

- Sidebar может перетягивать слишком много внимания.
- Навигация местами похожа на Discord/admin panel.
- Неготовые модули выглядят как полноценные основные разделы.
- Проекты/служебные пункты могут визуально конкурировать с задачами.

### Нужно

- сделать sidebar визуально тише;
- сделать навигацию компактнее;
- оставить фокус на:
  - Сегодня;
  - Входящие / Мои задачи;
  - Проекты;
  - Заметки;
  - Импорт;
  - Настройки;
- неготовые модули держать в группе “Позже” или показывать менее активно;
- активный пункт должен быть понятным, но не слишком ярким;
- sidebar должен помогать навигации, а не доминировать.

---

## 3. Слипшийся текст и плохие отступы

### Проблемы

- Текст слипается с иконками и счётчиками.
- После статов/счётчиков нет нормального расстояния до текста.
- Переключатель языка выглядит слипшимся.
- Chips, badges, counters и labels местами читаются плохо.

### Нужно

- сделать одинаковые отступы между иконкой, счётчиком и текстом;
- улучшить chips и badges;
- сделать нормальный переключатель языка;
- исправить слипшиеся элементы;
- использовать consistent spacing system;
- привести spacing к единому стилю.

### Проверить

- счётчики задач;
- счётчики колонок;
- priority chips;
- language switcher;
- topbar controls;
- filter chips;
- badges;
- labels;
- task metadata.

---

## 4. Меню действий перегружены

### Проблемы

- В меню слишком много пунктов.
- Базовые действия сложно найти.
- Чтобы удалить, иногда нужно листать.
- Редкие действия занимают основное место.
- Меню ощущается как техническое/админское.

### Нужно

- основные действия поставить первыми;
- редкие действия спрятать в “Дополнительно”;
- удаление сделать легко доступным, но с подтверждением;
- меню не должны требовать прокрутки для базовых действий;
- убрать технические пункты из основных меню.

### Приоритет действий

1. Открыть / Редактировать
2. Завершить / Вернуть
3. Дублировать, если уже поддерживается
4. Удалить

---

## 5. Задачи должны быть главным контентом

### Проблема

Интерфейс иногда ощущается слишком сфокусированным на проектах и создании проектов.

Пользователь приходит не “создавать сущности”, а работать с задачами.

### Нужно

- сделать задачи главным визуальным контентом;
- проекты должны помогать организации, но не доминировать;
- Today / My Tasks / Board должны быть основными рабочими зонами;
- создание проекта не должно забирать слишком много внимания;
- project cards сделать компактнее и спокойнее;
- проектная информация должна поддерживать task workflow, а не заменять его.

---

## 6. Board должен быть ближе к YouGile по ощущению

### Что нравится в YouGile

- компактные карточки задач;
- спокойный dark UI;
- мало визуального шума;
- фокус на задачах;
- читаемые колонки;
- быстрое сканирование задач глазами.

### Нужно

- сделать колонки спокойнее;
- сделать карточки задач компактнее;
- убрать лишнюю metadata с карточек;
- сделать secondary info тише;
- название задачи должно быть главным;
- прогресс подзадач показывать компактно;
- empty state “Нет задач” сделать спокойным;
- add task в колонке должен быть понятным, но не слишком ярким;
- horizontal scroll должен быть мягким;
- card spacing/padding должны быть одинаковыми;
- drag targets должны быть понятными;
- убрать визуальный шум.

---

## 7. Task rows / task cards должны быстрее сканироваться

### Нужно

- сделать единый TaskRow / TaskCard;
- название задачи визуально главное;
- checkbox слева;
- priority / due date / tags / subtasks — вторичные;
- завершённая задача — приглушённая и зачёркнутая;
- hover state понятный;
- active/opened state понятный;
- не показывать слишком много полей на карточке;
- technical fields убрать в detail/advanced.

### Task card должен показывать

- title;
- checkbox;
- priority chip;
- due date;
- tags, если есть;
- subtask progress;
- reminder/repeat icons, если есть.

Но всё должно быть компактно и не шумно.

---

## 8. Подзадачи плохо видны

### Проблема

Чтобы увидеть подзадачи, нужно открывать task detail. Это неудобно.

Структура задач плохо читается, если пользователь хочет быстро просмотреть план.

### Нужно

- показывать первые 1–3 подзадачи прямо в task row/card;
- добавить expand/collapse, если подзадач больше;
- показывать progress вида 1/3;
- основная задача должна быть заметнее;
- подзадачи должны быть визуально вложенными и тише;
- пользователь должен видеть структуру задач без обязательного открытия task detail.

### Цель

Сделать иерархию задач похожей на понятный план/структуру, чтобы можно было быстро просматривать проект глазами.

---

## 9. Task hierarchy / structure view

### Проблема

Основные задачи и подзадачи местами выглядят слишком одинаково. Из-за этого сложно быстро понять структуру проекта.

### Нужно

- усилить визуальную иерархию основных задач;
- secondary info сделать менее заметной;
- добавить более информативный, но компактный вид задач;
- сделать сканирование структуры удобным;
- если есть parent/subtask связи — отображать их понятнее;
- основные задачи должны быть заметнее подзадач.

---

## 10. Task Detail слишком технический

### Нужно

- сверху показывать checkbox + title;
- ниже оставить только основные поля:
  - проект;
  - приоритет;
  - срок;
  - описание;
  - подзадачи;
  - теги;
- advanced/game-dev поля спрятать в “Дополнительно”;
- bug fields показывать только для bug-задач;
- close button всегда должен быть виден;
- scroll должен быть стабильным;
- на mobile модалка не должна вылезать за экран;
- удалить/архивировать — через понятные действия, но без перегруза верхней части.

---

## 11. Заметки выглядят как placeholder

### Проблемы

- Заметки есть, но ими неудобно пользоваться.
- Нельзя нормально удалить/редактировать.
- Нет ощущения полноценного базового модуля.
- Заметки выглядят как “просто есть”, но не как usable feature.

### Нужно сделать basic Notes CRUD UX

- создать заметку;
- открыть заметку;
- редактировать заметку;
- удалить заметку с подтверждением;
- список заметок;
- empty state;
- если есть sync status — показывать его спокойно.

Не нужно делать большой Notion/GDD editor сейчас.

---

## 12. Ошибка импорта проекта

### Проблема

При импорте текста:

```txt
# Проект: RPG Demo
```

задачи могут появиться без создания/выбора проекта.

### Ожидаемое поведение

- если проект существует — использовать его;
- если проекта нет — создать его;
- задачи должны быть привязаны к проекту;
- preview должен показывать, какой проект будет создан или использован;
- preview должен показывать количество задач;
- после подтверждения пользователь должен видеть проект и задачи внутри него.

### Нужно

- проверить parser/import confirm flow;
- исправить создание/выбор проекта при импорте;
- добавить или обновить тесты для этого сценария.
